# SVG 打印尺寸计算器

上传一张 SVG，算出**要打多大，细节才不会被喷嘴吃掉**。

打开：<https://marx-t.github.io/svg-print-size/>

## 这不就是个缩放问题吗

不是。矢量图没有"分辨率"，放大不会变糊；但它最终要由一根 0.4 mm 的塑料线挤出成型。
所以真正的判据是：

- 图里**最细的结构**在成品上还剩多少毫米；
- 这个数字对不对得起**切片里的实际线宽**。

Lumina Studio Wiki 给的换算（[原文](https://wiki.luminastudio.com.cn/zh/docs/knowledge/nozzle-equivalent-resolution/)）：

```
等效像素数 ≈ 成品该边尺寸 ÷ 实际线宽
等效 PPI   ≈ 25.4 ÷ 实际线宽
```

于是：

```
需要的长边 = 安全系数 × 线宽 ÷ (最细结构 ÷ 画板长边)
```

安全系数取 1.0 / 1.5 / 2.0，分别对应"刚好不丢 / 推荐 / 舒服"。

0.4 喷嘴按 Bambu 默认 0.42 mm 线宽算，等效约 60 PPI；0.2 喷嘴 0.22 mm，约 115 PPI。

## 它是怎么量的

1. **读头部信息**：`viewBox`、带单位的 `width/height`、`stroke-width`、是否内嵌位图、
   是否用滤镜或 mask —— 这些直接决定用什么流程打。
2. **浏览器内栅格化**：把 SVG 按目标像素画进 canvas，再用调色板 + 15 位 LUT
   把抗锯齿过渡色吸附回实色，避免 1px 的 AA 边被当成"最细结构"。
3. **逐色块做欧氏距离变换**（Felzenszwalb 一维传递），取中轴脊点的宽度分布，
   得到每个色块的最细 / 中位 / 最粗。
4. **精测**：把最细的几个色块单独放大到约 60 px 再量一遍 —— 细线在整图尺度上
   只有 2–3 px，整数距离变换 + 抗锯齿各会带来可观误差。
5. **出结论**：尺寸判定表、三档推荐尺寸、热床分块数。

全部在浏览器本地完成，文件不上传。

## 精度

用已知线宽的图形校准过（3 / 6 / 12 / 24 / 60 / 160 用户单位）：

| 真值 | 测量 | 误差 |
|---|---|---|
| 160 | 160.0 | 0% |
| 60 | 60.0 | 0% |
| 24 | ~23.5 | −2% |
| 12 | ~11.8 | −2% |
| 6 | ~5.9 | −2% |
| 3 | 2.95 | −1.7% |

误差方向偏保守（略微少报宽度 → 建议尺寸偏大一点点）。

## 已知边界

- **尖角与收窄**：星芒、猫耳、字形衬线会收成 0 宽，任何尺寸都"不够"。
  所以默认忽略最极端的 15% 脊点；需要绝对保守可以把口径调到第 5 百分位。
- **文字**：浏览器用本机字体渲染，Lumina 导入时可能换字体，字号要单独确认。
- **变换**：`<g transform="scale(...)">` 里的 `stroke-width` 是变换前的值，
  页面对描边宽度只做展示，判定仍以栅格测量为准。
- **内嵌位图**：`<image>` 或 `data:image/...` 的真实上限由那张位图决定。
- 结论是几何估算，最终以切片预览和试打为准。
