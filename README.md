# SVG 打印尺寸计算器

上传一张 SVG，算出**要打多大，细节才不会被喷嘴吃掉**。

打开：<https://marx-t.github.io/svg-print-size/>

## 这不就是个缩放问题吗

不是。矢量图没有"分辨率"，放大不会变糊；但它最终要由一根 0.4 mm 的塑料线挤出成型。
所以真正的判据是：

- 图里**最细的结构**在成品上还剩多少毫米；
- 这个数字对不对得起**切片里的实际线宽**。

Lumina Studio Wiki 给的换算（[原文](https://wiki.luminastudio.com.cn/zh/docs/knowledge/nozzle-equivalent-resolution/)）：

```
等效像素数 ≈ 成品该边尺寸 ÷ 实际线宽
等效 PPI   ≈ 25.4 ÷ 实际线宽
```

于是：

```
需要的长边 = 安全系数 × 线宽 ÷ (最细结构 ÷ 画板长边)
```

安全系数取 1.0 / 1.5 / 2.0，分别对应"刚好不丢 / 推荐 / 舒服"。

0.4 喷嘴按 Bambu 默认 0.42 mm 线宽算，等效约 60 PPI；0.2 喷嘴 0.22 mm，约 115 PPI。

## 它是怎么量的

1. **读头部信息**：`viewBox`、带单位的 `width/height`、`stroke-width`、是否内嵌位图、
   是否用滤镜或 mask —— 这些直接决定用什么流程打。
2. **浏览器内栅格化**：把 SVG 按 1600–2200 px 画进 canvas，量化成 15 位色索引，
   再把邻近色箱合并（同一个颜色的渐变/色差会被量化拆成十几个相邻色箱，
   不合并就会互相咬合成一圈圈 1–2 px 的假"细线"），最后用 15 位 LUT 把每个
   像素吸附到最近的实色。
3. **逐色块做欧氏距离变换**（Felzenszwalb 一维传递），取中轴脊点 —— 脊点的
   2×距离就是该处色块的宽度。
4. **只认成片的笔画**：先按 4 邻接分连通块，丢掉面积不足最大块 2% 的碎点和
   没有实心内核的 1 px 链（抗锯齿碎边的典型形态）；再在宽度分布里找
   「带宽内点数达到阈值」的最小宽度。这样尖角收敛出的极细尖端、以及抗锯齿
   残留的 1 px 碎片都不会被当成"图里最细的笔画"——它们本来是量不出来的，
   却会让任何一张图都得出同一个数（等于栅格分辨率的倒数）。
5. **精测**：拿每个色块最细的几个脊点当锚点，开小窗口放大到该处约 60 px，
   迭代到数值收敛。窗口只围着锚点取，所以放大倍率可以远超整图栅格。
   放大后仍然只有 1–2 px 宽的，说明那不是能印出来的结构（渐变过渡带、
   抗锯齿残留），直接判掉；判掉后没有更清晰结构的图会明确标注「已到测量下限」。
6. **出结论**：尺寸判定表、三档推荐尺寸、热床分块数。

全部在浏览器本地完成，文件不上传。

## 精度

用已知线宽的图形校准过（0.5 到 40 用户单位，含 24 和 512 两种 viewBox）：

| 真值 | 测量 | 误差 |
|---|---|---|
| 0.5 | 0.50 | 0% |
| 1 | 1.00 | 0% |
| 2 | 2.00 | 0% |
| 3 | 3.00 | 0% |
| 5 | 5.00 | 0% |
| 10 | 10.00 | 0% |
| 20 | 20.00 | 0% |
| 40 | 40.00 | 0% |

1 px 以下的线（比如 0.5 单位在 1 px/单位的栅格里只有半个像素）靠精测还原，
也能读对。真实插画里，细线宽度会被抗锯齿和量化轻微放大，通常偏高 10–40%——
方向是**建议尺寸偏小**，所以关键件建议按「推荐」或「舒服」那一档取，
别卡着「下限」打。

## 已知边界

- **尖角与收窄**：星芒、猫耳、字形衬线会收成 0 宽，任何尺寸都"不够"。
  所以默认忽略最极端的 15% 脊点；需要绝对保守可以把口径调到第 5 百分位。
- **文字**：浏览器用本机字体渲染，Lumina 导入时可能换字体，字号要单独确认。
- **变换**：`<g transform="scale(...)">` 里的 `stroke-width` 是变换前的值，
  页面对描边宽度只做展示，判定仍以栅格测量为准。
- **内嵌位图**：`<image>` 或 `data:image/...` 的真实上限由那张位图决定。
- 结论是几何估算，最终以切片预览和试打为准。

## 为什么换几张图结论一样

如果不同图片给出完全相同的建议尺寸，几乎只有一个原因：**量到的"最细结构"
其实是栅格分辨率本身**，而不是图的内容。典型成因有三个，都已在这一版里处理：

- 15 位量化把同一块实色摊成十几个相邻色箱，每条色带的宽度恒等于
  距离变换的离散下限 2 px，于是「最细 ÷ 长边」永远是 `2 ÷ 栅格宽度`；
- 抗锯齿碎边、渐变过渡带被当成独立色块，宽度同样恒为 2 px；
- 带尖角的形状，中轴线向尖角分叉，分叉上的宽度一路趋近 0。

判断方法：看「最细结构 ÷ 长边」这个百分比。它精确等于 `200 ÷ 栅格宽度(px)`
（例如栅格 2000 px 时为 0.10%），就是撞上了上面的坑。
